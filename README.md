# Percussion Sync｜打擊樂譜與樂團空間

管理演出、曲目、分部、演奏者與打擊樂器需求。`codex` 分支使用 Cloudflare Workers + D1，原 Flutter 與 Google Sheet 程式保留。

## 會員與樂團

1. 開啟網站，用 3–40 碼英文、數字、底線、點或連字號的帳號，以及 12–128 字元密碼註冊。
2. 建立自己的樂團，或輸入管理者提供的專屬邀請碼。新註冊者不會取得任何既有樂團的資料。
3. 同一會員可加入多個樂團，透過上方選單切換；各樂團的演出、樂器庫、演奏者、版本與備份彼此隔離。

| 角色 | 權限 |
|---|---|
| 擁有者 | 全部資料、邀請與角色管理、指定管理員、轉移所有權 |
| 管理員 | 編輯與匯入資料、邀請／管理編輯者與唯讀成員、撤銷邀請 |
| 編輯者 | 檢視、備份、建立／修改／刪除配置、更新樂器與清點 |
| 唯讀成員 | 檢視及下載目前樂團備份 |

邀請碼指定受邀帳號、七天有效、單次使用，可在加入前撤銷。被移除的成員立即失去該樂團權限；擁有者需先轉移所有權才能離開。

會員使用獨立密碼登入，Session 存於 HttpOnly Cookie，登出會撤銷伺服器 Session；修改密碼會撤銷全部裝置登入。目前不收集 Email，未提供 Email 驗證或忘記密碼自助重設。

## 既有資料認領

舊版全部配置與名冊保留在「既有樂團」，沒有對新會員公開。持有原管理金鑰的人，請先註冊會員，再到「系統設定 → 認領原有樂團資料」輸入舊金鑰。只有第一次認領成功者取得擁有權，之後須由擁有者邀請其他會員。原管理金鑰不再用於一般登入。

## 演出管理與備份

支援曲目／分部建立、編輯、刪除，作曲／編曲資訊、樂器備註、演奏者、器材清單及清點。器材清單列出各曲目需求最大值與整場配置次數。

JSON 備份、匯入均限定目前選取的樂團。匯入需要擁有者或管理員權限，且目標樂團不能已有演出配置。支援舊資料列陣列與 `{ instruments, players, performances }` 格式。上傳的 band_id 不會改變目標樂團。

Google Sheet 搬移時先建立試算表副本，從設定頁下載舊 JSON、確認內容後再匯入。舊 API 可能補齊表格結構；新舊系統沒有雙向同步。原 static_web/data.json 快照不保證是最新資料，且不會公開於新網站。

## 本機執行

需要 Node.js 22.5 以上。

```sh
npm ci
cp .dev.vars.example .dev.vars
# 將 ADMIN_KEY 與 AUTH_PEPPER 設成不同的隨機值，至少 32 字元
npm run db:local
npm run dev
```

```sh
npm test
npm run build
npx wrangler deploy --dry-run
```

公開檔案以 allowlist 建置。GitHub codex-web.yml 執行測試、建置與部署預檢，不自動部署網站。部署、Secrets、migration 與回滾規則見 [部署文件](docs/DEPLOYMENT.md)。
